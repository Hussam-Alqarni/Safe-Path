# Safe Path — المسار الآمن

منصة سلامة النقل المدرسي: حضور بالبطاقة داخل الحافلة وعند بوابة المدرسة،
تتبّع مباشر، مسار يتكيّف مع الغياب، وإشعارات فورية لولي الأمر.

A school transport safety platform: NFC attendance on the bus and at the
school gate, live tracking, routes that adapt to absences, and instant
guardian notifications.

---

## تشغيل سريع · Quick start

```bash
flutter pub get
flutter run
```

لا يحتاج مفتاح API ولا خادماً ولا عتاداً. التطبيق يبدأ في **وضع العرض**:
أسطول محاكى، خريطة مرسومة داخلياً، وبيانات مدرسة كاملة في جدة.

No API key, no backend, no hardware. The app starts in **demo mode**: a
simulated fleet, a built-in map renderer, and a complete Jeddah school.

دليل التشغيل خطوة بخطوة على اللابتوب · Step-by-step on a laptop:
[`docs/RUN.md`](docs/RUN.md)

للتشغيل الحقيقي · For a live deployment: [`docs/SETUP.md`](docs/SETUP.md).

## ما الذي يفعله · What it does

| | |
|---|---|
| **حضور مزدوج** | البطاقة تُقرأ داخل الحافلة **وعند بوابة المدرسة**، فيغطي النظام كل طلاب المدرسة لا ركّاب الحافلات فقط |
| **كشف الطالب المتروك** | صعد ولم يسجّل نزوله عند إنهاء الرحلة ← تنبيه حرج فوري |
| **سدّ فجوة البوابة** | نزل من الحافلة ولم يدخل المدرسة خلال المهلة ← تنبيه حرج |
| **مسار متكيّف** | يبلغ ولي الأمر عن غياب ← تُتخطّى المحطة ويُعاد رسم المسار إن لم يبقَ فيها أحد |
| **تحضير يدوي آمن** | نسي البطاقة؟ السائق يسجّله بسبب إلزامي، والإشعار يوضّح لولي الأمر أنه **يدوي بدون بطاقة** مع زر اعتراض |
| **تتبّع لا يكذب** | تنقطع الإشارة ← تتوقف العلامة وتُعلن أن الموقع غير محدّث، بدل تخمين مكان طفل |

## الأدوار الخمسة · The five roles

| الدور | ما يراه |
|---|---|
| **ولي الأمر** | أبناؤه فقط، مسار اليوم لحظة بلحظة، خريطة مباشرة، الإبلاغ عن غياب |
| **السائق** | رحلته، المحطة الحالية، قائمة الطلاب، التحضير اليدوي، إنهاء الرحلة |
| **إدارة المدرسة** | لوحة الأعداد، خرائط الأسطول، سجل الطلاب كاملاً، التنبيهات |
| **موظف المدرسة** | قارئ البوابة وسجل الحضور |
| **المطوّر** | تشخيص، سجل الأحداث، سجل التدقيق، وتشغيل السيناريوهات |

بدّل بينها من أيقونة تبديل الدور في أعلى الشاشة — لا حاجة لتسجيل خروج.

---

## سيناريوهات العرض · Demo scenarios

من شاشة **المطوّر**:

1. **ابدأ الرحلة** — الحافلة تتحرك، الطلاب يصعدون، الإشعارات تصل.
2. **محاكاة طالب متروك** — يمنع تسجيل نزول أحد الركّاب. أنهِ الرحلة لترى
   التنبيه الحرج يصل للإدارة ولولي الأمر معاً.
3. **محاكاة انقطاع الإشارة** — الخريطة تتوقف وتقول إن الموقع غير محدّث.

ومن شاشة **ولي الأمر**: بلّغ عن غياب وشاهد المحطة تُتخطّى والمسار يُعاد رسمه.

## البنية · Architecture

```
lib/
├── domain/          منطق خالص بلا Flutter — سريع الاختبار وقابل لإعادة
│   ├── models/      الاستخدام من خادم مستقبلي
│   └── services/    JourneyEngine · RoutePlanner · EtaEngine
├── data/
│   ├── seed/        مدرسة كاملة ببيانات واقعية في جدة
│   ├── simulation/  أسطول محاكى خلف نفس واجهة الأجهزة الحقيقية
│   └── repositories/ الحالة والتحكّم
├── features/        شاشة لكل دور + طبقة الخريطة
└── core/            التصميم، الترجمة، الإعدادات
```

ثلاثة قرارات تحمل البنية كلها:

**متعدد المدارس من أول commit.** كل سجل يحمل `schoolId`، والحافلات تتبع
**شركة النقل** لا المدرسة — لأن المدارس تتعاقد ولا تملك أساطيلها.

**الحضور مرتبط بـ`studentId` لا بالبطاقة.** استبدال بطاقة مفقودة لا يقطع
تاريخ الطالب.

**السجلات لا تُعدَّل.** `AttendanceEvent` للإضافة فقط — سجل سلامة قابل
للتحرير لا قيمة قانونية له.

### مصدر البيانات قابل للتبديل

```dart
abstract class FleetEventSource {          // المواقع وقراءات البطاقات معاً،
  Stream<FleetEvent> get events;           // لأن جهاز التتبع يرسلهما على
  Future<void> start(List<Trip> trips);    // نفس الوصلة فعلاً
}

class SimulatedFleet implements FleetEventSource { ... }   // اليوم
class TeltonikaIngest implements FleetEventSource { ... }  // لاحقاً
```

كود العرض **هو** كود الإنتاج؛ يتغيّر سطر واحد في الإعدادات فقط.
